<task type="auto">
  <name>Task 1: Create /users admin page with user list and provisioning dialog</name>
  <files>src/app/(admin)/users/page.tsx</files>
  <action>
Create a new admin page at `src/app/(admin)/users/page.tsx` following the pattern from `beneficiaries/page.tsx`.

**Page structure:**
1. "use client" directive
2. Import tRPC hooks, shadcn components (Button, Dialog, Input, Label, Select, DataTable or Table, toast)
3. Fetch provisioned users: `trpc.userManagement.listProvisionedUsers.useQuery()`
4. Fetch beneficiaries: `trpc.beneficiary.list.useQuery({ entityId })` to show which ones don't have accounts yet

**DataTable columns for provisioned users:**
- User ID (truncated, monospace)
- Name (from joined beneficiary firstName + lastName)
- Email (beneficiary contact email)
- Role (userProfile.role — "beneficiary" or "admin")
- Linked Beneficiary (firstName lastName or "—" if none)
- Created At (formatted date)
- Actions column: "Reset Password" button

**"Create Portal Account" dialog:**
- Trigger: Primary button above the table "Create Portal Account"
- Form fields:
  a. Beneficiary select dropdown — filter to only show beneficiaries that do NOT have a userProfile (compare beneficiary.id against provisioned users' beneficiaryIds)
  b. Email input — pre-fill from selected beneficiary's email if available
  c. Temporary password input — with min 8 char validation
  d. Show/hide password toggle
- Submit calls `trpc.userManagement.createBeneficiaryUser.useMutation()`
- onSuccess: close dialog, invalidate listProvisionedUsers, show toast with success message including the email (remind admin to communicate temp password to beneficiary)
- onError: show error toast with message

**"Reset Password" action:**
- Opens a small dialog asking for new password
- Calls `trpc.userManagement.resetUserPassword.useMutation()`
- onSuccess: close dialog, show toast "Password reset successfully"

**Important:**
- Do NOT show or persist the temp password after creation — show it ONCE in a success dialog/toast with copy button, then it's gone
- Use sonner toast for notifications (already used across the app)
- Match the visual style of other admin pages (consistent headers, spacing)
  </action>

  <done>Page renders at /users with DataTable of provisioned users. "Create Portal Account" dialog works with beneficiary selection and temp password. Reset password dialog works. Toast notifications on success/error.</done>
