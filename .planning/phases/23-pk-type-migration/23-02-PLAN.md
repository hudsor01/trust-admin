**Key insight from research:**
- IDENTITY columns may cause drizzle-zod to include `id` as required
- Solution: Use `.omit({ id: true })` on insert schemas
- Router inputs change from `z.string()` to `z.coerce.number()` for IDs

<task type="auto">
  <name>Task 1: Update db/validation.ts for numeric IDs</name>
  <files>db/validation.ts</files>
  <action>
Update all insert/update schemas to properly handle BIGINT IDENTITY columns.

**Key changes:**

1. For all insertSchemas, ensure `id` is omitted (database generates it):
```typescript
// The createInsertSchema may include id - explicitly omit it
export const insertEntitySchema = createInsertSchema(entity, {
    // ... existing refinements
}).omit({ id: true })  // ID is GENERATED ALWAYS - cannot be inserted
```

2. For all updateSchemas, `id` should already be excluded (can't change PKs)

3. Check all FK ID fields - they're now numbers, not strings:
```typescript
// If there are any explicit z.string() for FK IDs, change to z.number()
// Example: if entityId was refined with z.string(), change to z.number()
```

4. **ID format validation:**
If there's any validation that checks ID format (like CUID pattern), remove it:
```typescript
// REMOVE patterns like:
id: z.string().cuid()  // No longer valid - IDs are numbers
// REPLACE with:
// (omit id from insert, or use z.number() for update if needed)
```

**For each of the 27 resource schemas:**
- insertXxxSchema: add `.omit({ id: true })` if not already present
- updateXxxSchema: should be `insertXxxSchema.partial()` - inherits the omit
- selectXxxSchema: leave as-is (includes id for reading)

**Test that drizzle-zod generates correct types:**
After changes, the insert schemas should NOT include `id` field.

<task type="auto">
  <name>Task 2: Update all tRPC router ID validations</name>
  <files>src/server/trpc/routers/*.ts (all 24 router files)</files>
  <action>
Update all tRPC router input validations to use numeric IDs instead of string IDs.

**Pattern to find and replace:**

```typescript
// FROM (in every router):
.input(z.object({ id: z.string() }))
.input(z.object({ id: z.string(), data: updateXxxSchema }))

// TO:
.input(z.object({ id: z.coerce.number() }))
.input(z.object({ id: z.coerce.number(), data: updateXxxSchema }))
```

**Why z.coerce.number():**
- URL params come as strings (e.g., `/api/liabilities/123`)
- z.coerce.number() safely converts "123" → 123
- Also handles actual numbers passed directly
