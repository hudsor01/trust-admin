# Phase 23: Primary Key Type Migration - Research

**Researched:** 2026-01-17
**Domain:** PostgreSQL IDENTITY columns with Drizzle ORM
**Confidence:** HIGH

<research_summary>
## Summary

Researched the migration from TEXT primary keys to BIGINT GENERATED ALWAYS AS IDENTITY for PostgreSQL with Drizzle ORM. The current schema uses 31 tables with `t.text().primaryKey().notNull()` and application-side ID generation via `$defaultFn(generateId)`. There are 63 foreign key constraints that reference these TEXT PKs.

The modern PostgreSQL approach (since v10) is IDENTITY columns, which supersede SERIAL. Drizzle ORM fully supports this with `bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity()`.

**Primary recommendation:** Use `bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity()` for all 31 tables. Since this is pre-production with no data migration concerns, drop/recreate via `drizzle-kit push --force` is the cleanest approach. Update all 63 FK columns to match (bigint instead of text).
</research_summary>

<architecture_patterns>
## Architecture Patterns

### Recommended Primary Key Pattern
```typescript
// NEW: BIGINT with IDENTITY (database generates ID)
import { bigint, pgTable, text } from 'drizzle-orm/pg-core'

export const entity = pgTable('Entity', (t) => ({
  id: bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity(),
  name: t.text().notNull(),
  // ... rest of columns
}))
```

### Foreign Key Pattern
```typescript
// FK columns must also be bigint to match PK type
export const vehicle = pgTable('Vehicle', (t) => ({
  id: bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity(),
  entityId: bigint({ mode: 'number' }).notNull(),  // Changed from text()
  // ... rest
}), (table) => [
  foreignKey({
    columns: [table.entityId],
    foreignColumns: [entity.id],
    name: 'Vehicle_entityId_fkey',
  }).onUpdate('cascade').onDelete('restrict'),
])
```

### TypeScript Type Changes
```typescript
// BEFORE: IDs are strings
type Entity = { id: string; name: string; ... }

// AFTER: IDs are numbers
type Entity = { id: number; name: string; ... }
```

### Insert Pattern Changes
```typescript
// BEFORE: Generate ID client-side
const id = createId()
await db.insert(entity).values({ id, name: 'Test' })

// AFTER: Let database generate ID, get it back
const [inserted] = await db.insert(entity)
  .values({ name: 'Test' })
  .returning({ id: entity.id })
// inserted.id is now available
```

### Anti-Patterns to Avoid
- **Don't use GENERATED BY DEFAULT AS IDENTITY:** Allows manual override, defeats protection
- **Don't use SERIAL:** Legacy syntax, IDENTITY is modern standard
- **Don't mix TEXT and BIGINT FKs:** All references to a PK must match its type
- **Don't use mode:'bigint' unless needed:** JavaScript `number` handles IDs up to 2^53 safely
</architecture_patterns>

<dont_hand_roll>
## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| ID generation | Custom CUID/UUID functions | PostgreSQL IDENTITY | DB guarantees uniqueness, no race conditions |
| Sequence management | Manual sequence handling | `generatedAlwaysAsIdentity()` | Drizzle handles sequence creation |
| Type conversion | Custom string↔number parsing | Native bigint type | Type safety, no runtime errors |
| FK type matching | Separate type systems | Consistent bigint everywhere | Prevents type mismatch errors |

**Key insight:** With IDENTITY columns, the database owns ID generation. This is simpler, faster, and more reliable than application-side ID generation. Remove all `$defaultFn(generateId)` patterns.
</dont_hand_roll>

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: drizzle-zod IDENTITY Handling
**What goes wrong:** `createInsertSchema()` may include `id` as required field for IDENTITY columns
**Why it happens:** Known issue in drizzle-zod not detecting `generatedAlwaysAsIdentity()`
**How to avoid:** Explicitly omit `id` from insert schemas: `insertSchema.omit({ id: true })`
**Warning signs:** Validation errors on insert, "id is required" messages
**Source:** [GitHub Issue #4724](https://github.com/drizzle-team/drizzle-orm/issues/4724)

### Pitfall 2: FK Type Mismatch
**What goes wrong:** Foreign key constraints fail to create
**Why it happens:** FK column type (text) doesn't match PK type (bigint)
**How to avoid:** Update ALL FK columns to `bigint({ mode: 'number' })` when changing PKs
**Warning signs:** Migration errors, constraint violation messages

### Pitfall 3: Application Code Expecting Strings
**What goes wrong:** Runtime errors when code treats IDs as strings
**Why it happens:** TypeScript types change from `string` to `number`
**How to avoid:** TypeScript compiler will catch most issues; search codebase for string ID patterns
**Warning signs:** Type errors like "Type 'number' is not assignable to type 'string'"

### Pitfall 4: Insert Without Returning
**What goes wrong:** Can't access the generated ID after insert
**Why it happens:** Forgetting `.returning()` clause
**How to avoid:** Always use `.returning({ id: table.id })` when you need the ID
**Warning signs:** `undefined` IDs after insert

### Pitfall 5: Manual ID Override Attempts
**What goes wrong:** Error when trying to insert explicit ID
**Why it happens:** GENERATED ALWAYS rejects manual values
**How to avoid:** This is intentional protection; remove ID from insert values
**Warning signs:** "cannot insert a non-DEFAULT value into column" error
</common_pitfalls>

<code_examples>
## Code Examples

### Schema Definition
```typescript
// Source: Drizzle ORM docs - https://orm.drizzle.team/docs/column-types/pg
import { bigint, pgTable, text, timestamp, foreignKey, index } from 'drizzle-orm/pg-core'

export const entity = pgTable('Entity', (t) => ({
  id: bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity(),
  name: t.text().notNull(),
  createdAt: t.timestamp({ precision: 3, mode: 'string', withTimezone: true })
    .defaultNow()
    .notNull(),
}))

export const vehicle = pgTable('Vehicle', (t) => ({
  id: bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity(),
  entityId: bigint({ mode: 'number' }).notNull(),
  make: t.text().notNull(),
  model: t.text().notNull(),
}), (table) => [
  foreignKey({
    columns: [table.entityId],
    foreignColumns: [entity.id],
    name: 'Vehicle_entityId_fkey',
  }).onUpdate('cascade').onDelete('restrict'),
  index('idx_vehicle_entity').on(table.entityId),
])
```

### Insert with ID Return
```typescript
// Source: Drizzle ORM docs - insert patterns
const [newVehicle] = await db.insert(vehicle)
  .values({
    entityId: existingEntityId,  // number, not string
    make: 'Toyota',
    model: 'Camry',
  })
  .returning()

console.log(newVehicle.id)  // Generated bigint ID
```

### Validation Schema Adjustment
```typescript
// Source: Community pattern for drizzle-zod IDENTITY workaround
import { createInsertSchema, createSelectSchema } from 'drizzle-zod'
import { entity } from './schema'

// Select schema includes id (for reading)
export const selectEntitySchema = createSelectSchema(entity)

// Insert schema omits id (database generates it)
export const insertEntitySchema = createInsertSchema(entity).omit({ id: true })

// Update schema also omits id (can't change PKs)
export const updateEntitySchema = insertEntitySchema.partial()
```

<sota_updates>
## State of the Art (2025-2026)

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| SERIAL/BIGSERIAL | GENERATED ALWAYS AS IDENTITY | PostgreSQL 10 (2017) | SQL standard compliance, better protection |
| text() with $defaultFn | bigint().generatedAlwaysAsIdentity() | Drizzle 0.32.0 | Database-side ID generation |
| Application ID generation (CUID) | Database IDENTITY | Best practice 2024+ | Simpler, no race conditions |

**New tools/patterns to consider:**
- **Hybrid ID strategy:** Internal bigint for joins, public NanoID/UUID for APIs (not needed for this project)
- **UUIDv7:** Time-ordered UUIDs if UUID format is needed (not applicable here)

**Deprecated/outdated:**
- **SERIAL type:** Replaced by IDENTITY in modern PostgreSQL
- **$defaultFn for IDs:** Unnecessary when database generates IDs
- **TEXT primary keys:** Poor performance for joins compared to bigint
</sota_updates>
