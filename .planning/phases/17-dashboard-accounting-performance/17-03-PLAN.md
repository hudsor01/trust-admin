<objective>
Eliminate the portal's client-side session-then-fetch waterfall by prefetching beneficiary data in a Server Component.

Purpose: The portal page currently renders as a client component that calls `useSession()`, waits for the session, then fires `beneficiary.me.useQuery()` -- two sequential round trips before any meaningful content appears. The portal layout already validates the session server-side, so by the time page.tsx renders the user is authenticated. Converting to a Server Component with `createTRPCHelpers` + `HydrationBoundary` means beneficiary data arrives with the page HTML, eliminating the loading spinner.

Output: Portal loads with beneficiary data on first paint; no visible loading spinner for authenticated users.
</objective>
