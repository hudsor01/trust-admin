1. Adding RLS + admin-only policies to 16 tables that currently have none

all Drizzle HTTP queries to run as the `authenticated` role). The `app.is_admin()` and
`app.get_user_beneficiary_id()` helper functions are already deployed. This phase closes the
coverage gaps and hardens write operations.
</objective>

## Background: Current State

The research report (`53-RESEARCH.md`) confirmed that RLS is ALREADY active, contrary to the
original CONTEXT.md. Key facts for the implementer:

- **11 tables already have RLS** with policies in `drizzle/schema.ts` (the Drizzle-generated
  schema, which reflects the database). These are: `entity`, `homestead`, `trust_accounting`,
  `vehicle`, `bank_account`, `investment_account`, `liability`, `distribution`, `hems_request`,
  `beneficiary`, `withdrawal_record`.
- **`db/schema.ts` (the source schema) has NO `pgPolicy()` calls** — policies live only in the
  database and the generated `drizzle/schema.ts`. This phase adds `pgPolicy()` to `db/schema.ts`
  so the source is authoritative.
- **Neon Authorize handles role switching**: `setRequestAuthToken(jwt)` in tRPC context causes
  the neon HTTP driver to run queries as `authenticated` role with `auth.user_id()` set. RLS
  IS enforced in production for all tRPC calls.
- **`neondb_owner` has `BYPASSRLS=true`**: Tests use `SET ROLE authenticated` +
  `app.set_test_user()` to test RLS. The `scripts/add-owner-rls-policies.ts` script adds
  explicit `neondb_owner` policies so tests that don't switch roles still see filtered data.
- **Write policies are permissive with no conditions**: The existing INSERT/UPDATE/DELETE
  policies on all 11 tables apply to `authenticated` role with no `WITH CHECK` or `USING`
  clause, meaning any authenticated user could in theory write to any row at the DB level
  (mitigated only by tRPC `adminProcedure` guards).
- **`specific_bequest` has `beneficiaryId` but zero RLS**: It is admin-only in tRPC today,
  but should have RLS as defense-in-depth.
- **17 additional tables need admin-only RLS**: `artwork`, `rental_property`, `insurance_policy`,
  `personal_property`, `trustee`, `trustee_fee_schedule`, `trustee_fee_entry`,
  `liability_payment`, `contact`, `contact_association`, `task`, `document`, `valuation`,
  `transaction`, `activity_log`, `pending_inventory_item`, `specific_bequest` (beneficiary filter).
- **`user_profile` must NOT get RLS** — it is queried inside `app.get_user_beneficiary_id()`
  and would cause infinite recursion.
- **Test expects exactly 33 tables with RLS** (`tests/rls.test.ts` line 957). Currently only
  11 have RLS. Adding 17 more = 28, not 33. The test count must be updated to match the
  actual target (28 tables).

- task
- document
- valuation
- transaction
- activityLog (table name: `activity_log`)
- pendingInventoryItem (table name: `pending_inventory_item`)

Admin-only policy pattern to add inside each table's constraint array:

```typescript
pgPolicy('crud-authenticated-policy-select', {
    as: 'permissive',
    for: 'select',
    to: ['authenticated'],
    using: sql`( SELECT app.is_admin() AS is_admin)`,
}),
pgPolicy('crud-authenticated-policy-insert', {
    as: 'permissive',
    for: 'insert',
    to: ['authenticated'],
}),
pgPolicy('crud-authenticated-policy-update', {
    as: 'permissive',
    for: 'update',
    to: ['authenticated'],
}),
pgPolicy('crud-authenticated-policy-delete', {
    as: 'permissive',
    for: 'delete',
    to: ['authenticated'],
}),
```

Chain `.enableRLS()` after the table definition (after the closing parenthesis of `pgTable(...)`):

```typescript
export const artwork = pgTable(
    'artwork',
    { /* columns */ },
    (table) => [
        // existing indexes/FKs...
        pgPolicy('crud-authenticated-policy-select', { ... }),
        pgPolicy('crud-authenticated-policy-insert', { ... }),
        pgPolicy('crud-authenticated-policy-update', { ... }),
        pgPolicy('crud-authenticated-policy-delete', { ... }),
    ],
).enableRLS()
```

NOTE: The constraint array is the third argument. If a table already has a third argument
(array of indexes/FKs), add pgPolicy entries into the existing array.
</action>
