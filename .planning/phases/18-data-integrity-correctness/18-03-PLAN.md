In db/validation.ts:

1. Create a helper function near the top of the file (after the existing validation helpers, before the schema definitions):

```typescript
/**
 * Wraps a partial schema to require at least one field to be defined.
 * Prevents silent no-op UPDATE statements from empty payloads.
 */
function requireAtLeastOneField<T extends z.ZodTypeAny>(schema: T) {
    return schema.refine(
        (data: Record<string, unknown>) =>
            Object.values(data).some((v) => v !== undefined),
        { message: 'At least one field must be provided for update' },
    )
}
```

2. Apply `requireAtLeastOneField` to ALL 27 update schema exports. Transform each from:
   ```typescript
   export const updateXxxSchema = insertXxxSchema.partial()
   ```
   to:
   ```typescript
   export const updateXxxSchema = requireAtLeastOneField(insertXxxSchema.partial())
   ```

3. IMPORTANT: Zod's `.refine()` returns a `ZodEffects` type, not `ZodObject`. This means TypeScript inference changes slightly. If any tRPC router uses the update schema's `.shape` property or `.extend()`, this will break. Check for this:
   ```bash
   grep -r "updateSchema\.\(shape\|extend\|merge\)" src/server/ db/
   ```
   If found, the refine must be applied at the router level instead. If NOT found (expected), proceed with the validation.ts approach.

4. Create tests/lib/validation.test.ts:
   - Import all update schemas
   - Test that each rejects `{}` with a "at least one field" error
   - Test that representative schemas accept valid single-field updates
   - Test edge case: object with all undefined values `{ name: undefined }` should also be rejected

Note: Zod 4 (installed as 4.3.6) supports `.refine()` after `.partial()`. The refined type still infers correctly for tRPC `.input()` usage.

4. Before inserting the new token (line 34), add two operations:

   a. **Invalidate existing unexpired tokens** for this email (one-unexpired-per-email):
   ```typescript
   // Invalidate any existing unexpired tokens for this email
   await db
       .update(passwordResetToken)
       .set({ usedAt: new Date() })
       .where(
           and(
               eq(passwordResetToken.email, email.toLowerCase()),
               isNull(passwordResetToken.usedAt),
           )
       )
   ```

   b. **Clean up expired tokens** (housekeeping, reduces table bloat):
   ```typescript
   // Clean up expired tokens older than 24 hours
   await db
       .delete(passwordResetToken)
       .where(
           lt(passwordResetToken.expiresAt, new Date(Date.now() - 24 * 60 * 60 * 1000))
       )
   ```

   Note: Delete tokens expired more than 24 hours ago (not just expired), to avoid deleting tokens that expired moments ago but might still be in-flight for error handling.

5. The full flow becomes:
   - Look up user by email
   - If found: invalidate existing tokens -> cleanup old expired -> insert new token -> send webhook
   - Always return 200 (prevents email enumeration)
