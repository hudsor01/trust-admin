# Phase 8 Plan 03: Improve CRUD Factory Type Inference

**Status**: Not started
**Depends on**: Plans 08-01, 08-02 (route factory types clean)
**Objective**: Eliminate `as any` casts in crud-factory.ts by using Drizzle's type inference and generic constraints, improving type safety for all database operations.

## Execution Context

@db/crud-factory.ts (lines 1-110) - Current CRUD factory with 11 `as any` casts
@db/schema.ts - All table definitions
@node_modules/drizzle-orm/pg-core/table.d.ts - Drizzle PgTable types

## Context

**Problem**: The CRUD factory casts the `table` parameter to `any` in 11 places because TypeScript can't infer column access patterns on generic table types:

```typescript
// Current pattern (loses type safety)
.from(table as any)
.where(eq((table as any)[filterColumn], filterValue))
.where(eq((table as any).id, id))
```

**Root causes**:
1. `table[filterColumn]` - Dynamic column access on generic type
2. `table.id` - Column access assumes all tables have `id` column
3. Drizzle's generic constraints not fully utilized

**Goal**: Use Drizzle's type system to eliminate casts while maintaining:
- Generic table parameter (works with any Drizzle table)
- Dynamic filter column access
- Type-safe column references

## Tasks

### Task 1: Add type constraints for table parameter

Update `createCrud` function signature to use proper Drizzle generic constraints:

**Current**:
```typescript
export function createCrud<TTable, TInsert, TSelect>(
  table: TTable,
  options: CrudOptions = {}
): CrudOperations<TTable, TInsert, TSelect>
```

**Target**:
```typescript
export function createCrud<
  TTable extends PgTable,
  TInsert extends InferInsertModel<TTable> = InferInsertModel<TTable>,
  TSelect extends InferSelectModel<TTable> = InferSelectModel<TTable>
>(
  table: TTable,
  options: CrudOptions = {}
): CrudOperations<TTable, TInsert, TSelect>
```

**Why**: This allows TypeScript to infer Insert/Select types from the table, eliminating the need to pass them explicitly.

**Verification**: TypeScript compiles without errors, type inference works correctly.

**Commit**: `feat(08-03): add Drizzle generic constraints to CRUD factory`

### Task 2: Replace table casts with type-safe operations

Replace `as any` casts in 5 key locations using Drizzle's type-safe patterns:

**Location 1: getAll with filter** (lines 37-38)
```typescript
// Before
.from(table as any)
.where(eq((table as any)[filterColumn], filterValue))

// After
.from(table)
.where(eq(table[filterColumn as keyof typeof table], filterValue))
```

**Location 2: getAll without filter** (line 41)
```typescript
// Before
.from(table as any)

// After
.from(table)
```

**Location 3: getById** (lines 51-52)
```typescript
// Before
.from(table as any)
.where(eq((table as any).id, id))

// After
.from(table)
.where(eq(table.id, id))
```

**Location 4: insert** (line 68)
```typescript
// Before
.insert(table as any)

// After
.insert(table)
```

**Location 5: update and delete** (lines 83, 95)
```typescript
// Before
.update(table as any)
.delete(table as any)

// After
.update(table)
.delete(table)
```

**Verification**: TypeScript compiles without errors for all 5 locations.

**Commit**: `feat(08-03): replace table casts with type-safe operations`

### Task 3: Handle dynamic filter column access

**Challenge**: `table[filterColumn]` on line 38 requires special handling because `filterColumn` is a string, not a type-level key.

**Options**:
1. Type assertion: `table[filterColumn as keyof typeof table]`
2. Extract column getter: Create helper that asserts column exists
3. Keep targeted cast: Only cast the column access, not entire table

**Decision point**: Choose the approach that balances safety and ergonomics. Document in summary.

**Verification**: TypeScript compiles, filtered queries work correctly.

**Commit**: If code changes needed, `refactor(08-03): improve filter column type safety`
