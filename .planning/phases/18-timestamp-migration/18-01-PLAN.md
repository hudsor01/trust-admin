<objective>
Migrate all timestamp columns from `timestamp` to `timestamptz` for proper timezone handling.

Purpose: PostgreSQL best practice - timestamps with timezone prevent ambiguity when data is accessed from different timezones or when server timezone changes.
Output: All 116 timestamp columns updated to use `withTimezone: true`, database migrated, application verified working.
</objective>

**Research findings:**
- Drizzle ORM timestamp with timezone: `timestamp({ precision: 3, mode: 'string', withTimezone: true })`
- Current pattern: `timestamp({ precision: 3, mode: 'string' })` (116 occurrences)
- PostgreSQL stores timestamptz internally as UTC, converts on display
- mode: 'string' means dates are passed as raw strings - no JS Date mapping issues
- Migration is non-breaking for application code since we use mode: 'string'

**Drizzle documentation (Context7):**
> For `timestamp with time zone`, the internally stored value is always in UTC. Input values with an explicit time zone are converted to UTC using the appropriate offset.

**Migration strategy:**
- Update schema.ts to add `withTimezone: true` to all timestamp columns
- Run `bun run db:push` to apply schema changes
- Drizzle-kit will generate ALTER TABLE statements to change column types
- Existing data will be treated as if it were in server timezone and converted to UTC
</context>
