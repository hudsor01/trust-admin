## Typography

Inherited from Phase 23 global system. No overrides for this page.

**Project-baseline exemption (STATE.md `[Phase 23]`):** Phase 23 locked **3 font
weights** (400 / 500 / 600) as the project-wide standard used by every admin
page and the shared `KpiStrip`/`PageHeader`/`DataTable` primitives. The
"max 2 weights" UI-checker rule applies to NEW per-page declarations; this
page introduces **zero** new weights — it inherits the locked baseline
verbatim. Forcing 2 weights here would diverge from 12 existing admin pages
and ship a visibly inconsistent firearm page.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px (text-sm) | 400 | 1.5 | Table cells, form labels, help text |
| Label | 14px (text-sm) | 500 (font-medium) | 1.4 | Section headers inside dialog (`h4`), column headers |

`tabular-nums` class applied to all money and numeric KPI values.
`text-xs` (12px, weight 400) for secondary sub-lines in combined table cells
(e.g., make/model sub-label under firearm name).

## KPI Strip

4 cards in a `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4`.

| # | Label | Derivation | Type |
|---|-------|-----------|------|
| 1 | Firearm count | `firearms.length` | number |
| 2 | Total DOD value | `sumStrings(firearms.map(f => f.dodValue))` formatted with `formatCurrency` | currency string |
| 3 | Transfer % complete | `(transferredCount / firearms.length) * 100` formatted with `formatPercent` | percent string |
| 4 | NFA items | `firearms.filter(f => f.isNfa).length` | number |

KPI 4 ("NFA items") surfaces the regulatory-complexity count. If zero, the
value renders as `0` — no inversion needed.

Loading skeleton: 4 `SummaryCard isLoading` cards (inherited from KpiStrip
behavior when `isLoading={true}`).

## CSV Export — Column Scope

`location` is EXCLUDED from the default CSV export per PITFALLS.md §13
("physical location enables theft").

The DataTable's CSV exporter uses `getVisibleLeafColumns`, which already
excludes columns hidden via `initialColumnVisibility`. Because `location` is
hidden by default (see above), it will not appear in the CSV unless the user
explicitly toggles it visible first.

For columns that ARE visible by default, the CSV export includes them without
special treatment. `serialNumber` IS included in the CSV — it is the
authoritative legal identifier for ATF recordkeeping, and all access is
already gated behind `adminProcedure`.

Action columns (column id `actions`, `select`) must set
`meta: { excludeFromExport: true }` per the DataTable's column-meta contract.

## Row-Detail Panel

Rendered via `getRowDetail` prop when the user clicks the expand chevron.
Uses `firearm.byId` (Phase 29 D-05) which eager-loads `valuations` and
`documents`.

The row-detail fetches the full record from `trpc.firearm.byId` (not from the
list row, which lacks relations). Use a local `FirearmRowDetail` component
that accepts the list-row data and fires a `byId` query on mount.

**Layout:** 3 sections in a `grid grid-cols-1 md:grid-cols-2 gap-6 p-4`
container with `bg-muted/30 rounded-md border border-border`:

### Section 1 — Physical Details
Fields: `barrelLength`, `action`, `caliber` (full), `condition`, `location`
(label: "Storage Location"), `insured` flag, `acquisitionDate`, `acquisitionCost`,
`notes`.

`location` is displayed here (in the detail panel) — it is not hidden from
this view, only from the CSV export. Display with `text-muted-foreground text-xs`
label and `font-mono text-sm` value.

### Section 2 — NFA Classification (conditional on `isNfa === true`)
When `isNfa === false`: section is hidden entirely.

When `isNfa === true`:
- Section header: `<h4>NFA Classification</h4>` + milestone-colored "NFA" pill
- Fields displayed: `nfaClass`, `atfFormType`, `atfControlNumber`, `taxStampDate`,
  `nfrtrSerial`, `nfaRegistered`
- `nfaTransferStatus` badge: prominently displayed with appropriate color
  (NOT_FILED → secondary, FILED → outline, APPROVED → success-tinted)
- **"File Form 5" button** (see below)
- Unregistered NFA alert: when `nfaRegistered === false`, render a
  `bg-warning/10 border border-warning/30 rounded p-3 text-sm` alert block
  with text: "This NFA item is not registered in the NFRTR. Unregistered NFA
  items are contraband. Do not attempt to transfer. Consult an attorney
  immediately."
- Recordkeeping disclaimer (always visible in this section, muted):
  `<p className="text-xs text-muted-foreground mt-3">This section is for recordkeeping only. Consult a licensed firearms attorney or FFL dealer for ATF transfer requirements.</p>`

### Section 3 — Related Records (always visible)
- Valuations: mini table of `valuation` records (date, amount, type).
  Empty state: "No valuation history."
- Documents: list of `document` records (name, type, upload date) with links.
  Empty state: "No documents attached."

## "File Form 5" Button — NFA Status Transition

Visible ONLY in the row-detail NFA section when `isNfa === true`.
Calls `trpc.firearm.setNfaTransferStatus.useMutation()` (Phase 29 D-02).

**Affordance:** A Button (variant `outline`, size `sm`) labeled "Update Form 5
Status" next to the `nfaTransferStatus` badge. Opens a small Dialog (not the
full FirearmDialog) with:
- `Select` for status: NOT_FILED | FILED | APPROVED (labels: "Not Filed" | "Filed
  — Awaiting ATF" | "Approved")
- Optional `Input type="date"` for `taxStampDate` (shown when status = APPROVED)
- Optional `Input` for `atfControlNumber` (shown when status = FILED or APPROVED)
- Disclaimer line below inputs:
  `<p className="text-xs text-muted-foreground">This app does not file ATF forms. Record the status after filing through your FFL or attorney.</p>`
- Submit button: "Save Status"

On success: `utils.firearm.list.invalidate()`, sonner toast "NFA transfer
status updated."
On error (BAD_REQUEST from router — non-NFA item): toast.error with the
server message.

This dialog is a small component (< 80 lines), not the full FirearmDialog.
Name: `NfaStatusDialog`. Colocate in `_components/`.

## FirearmDialog — Create / Edit Form

**Pattern:** 3-step wizard using the `ResourceDialog` + `WizardStepGroup` +
`useResourceForm` + `FIREARM_WIZARD_STEPS` pattern exactly matching Vehicle and
PersonalProperty dialogs. Do not build a non-wizard single-form dialog — the
firearm field count (30+ columns) warrants the wizard UX.

`FIREARM_WIZARD_STEPS` is a new export in `src/lib/asset-wizard-steps.ts`.

### Step 1 — Identity (label: "Identity")
Required fields (gate `schema`): `name`, `make`, `model`, `serialNumber`, `firearmType`

Fields shown:
- `NameDescriptionFields` (name + description, idPrefix="firearm")
- 3-column grid: `make`, `model`, `firearmType` (Select)
- 2-column grid: `serialNumber` (Input), `caliber` (Input)
- 2-column grid: `barrelLength` (Input type="number", label "Barrel Length (inches)"), `action` (Input, label "Action Type", placeholder "e.g., bolt-action, semi-auto")
- NFA toggle row (Switch):
  ```
  <Label>NFA Item</Label>
  <Switch checked={isNfa} onCheckedChange={...} />
  <span className="text-xs text-muted-foreground">Check if this is a Title II / NFA firearm</span>
  ```

**NFA conditional section** — rendered when `isNfa === true` using
`formInstance.Subscribe` on the `isNfa` field:
- Section header: `<h4 className="text-sm font-medium">NFA Classification</h4>`
- 3-column grid: `nfaClass` (Select, required when isNfa), `atfFormType` (Select),
  `nfaRegistered` (Switch, label "NFRTR Registered")
- 2-column grid: `atfControlNumber` (Input), `taxStampDate` (Input type="date")
- `nfrtrSerial` (Input, full-width, label "NFRTR Serial Number", placeholder
  "If different from serial number above")
- Disclaimer: `<p className="text-xs text-muted-foreground mt-2">NFA fields are for recordkeeping only. ATF approval is required before transferring NFA items to a beneficiary.</p>`

Step gate `schema`: `z.object({ name: nonEmpty, make: nonEmpty, model: nonEmpty, serialNumber: nonEmpty, firearmType: nonEmpty })`

### Step 2 — Valuation (label: "Valuation")
Required fields (gate `schema`): none required, but `acquisitionCost` and
`dodValue` validated with `optionalMoney` if non-empty.

Fields shown:
- `condition` (Select, full-width, label "NRA Condition Grade")
- 2-column grid: `acquisitionDate` (Input type="date"), `acquisitionCost` (Input, placeholder "$")
- 3-column grid: `dodValue` (Input, placeholder "$ — Blue Book / appraisal"),
  `dodValueDate` (Input type="date"), `dodValueType` (Select with DOD_VALUE_TYPES)

Step gate `schema`: `z.object({ acquisitionCost: optionalMoney, dodValue: optionalMoney })`

### Step 3 — Ownership (label: "Ownership")
Required fields (gate `schema`): `status`, `transferStatus`.

Fields shown:
- 3-column grid: `status` (Select), `transferStatus` (Select),
  `insured` (Switch, label "Insured")
- `location` (Input, full-width, label "Storage Location",
  placeholder "Safe, bank vault, FFL storage...")
- `notes` (Textarea, rows=3)

Step gate `schema`: `z.object({ status: nonEmpty, transferStatus: nonEmpty })`

**Serial number conflict:** When `trpc.firearm.create` returns `CONFLICT`, display
`toast.error('A firearm with this serial number already exists.')`. Do not
close the dialog on conflict — leave it open so the user can correct the
serial number.

## Interaction Patterns

### Inline editing
Matches VehicleTable: `EditableTextCell` for `name`, `EditableCurrencyCell` for
`dodValue`, `EditableSelectCell` for `condition`, `status`, `transferStatus`.
All inline edits call `trpc.firearm.update.useMutation`, then
`utils.firearm.list.invalidate()` in `onSuccess`.

### Bulk delete
Sequential (not Promise.all) — matches `onBulkDelete` in VehiclesClient verbatim.
Partial-fail reports remaining count.

### Confirm dialog for single delete
`useConfirmDialog` + `ConfirmDialog` component — matches VehiclesClient.

### Loading state
`loading.tsx` exports a `FirearmsLoading` component with a `KpiStrip` skeleton
(4 `SummaryCard isLoading`) + a plain DataTable skeleton. The
`HydrationBoundary` in `page.tsx` prefetches `trpc.firearm.list` via
`getQueryKey`. `error.tsx` uses the standard `ErrorBoundary` pattern matching
other admin pages.

### Toast conventions
All mutations use sonner `toast.success` / `toast.error` — never native
`alert()` or `confirm()`. Error paths use `logger.error()` before toasting.
