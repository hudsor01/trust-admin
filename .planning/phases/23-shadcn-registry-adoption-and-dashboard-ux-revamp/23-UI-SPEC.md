## Spacing Scale

Declared values (Tailwind 4 default scale, multiples of 4 only):

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px  | `gap-1`, `p-1`     | Icon-to-text gap, badge inline padding |
| sm | 8px  | `gap-2`, `p-2`     | Compact element spacing, kanban card internal padding |
| md | 16px | `gap-4`, `p-4`     | **Default element spacing** — card content, form fields |
| lg | 24px | `gap-6`, `p-6`     | Section padding, page-section gaps, KPI grid gap |
| xl | 32px | `gap-8`, `p-8`     | Layout gaps between major regions |
| 2xl | 48px | `gap-12`, `p-12`  | Major section breaks (settings card groups) |
| 3xl | 64px | `gap-16`           | Page-level vertical rhythm (rare, only in empty states) |

**Phase 23 specific spacing rules:**

- **Page-level vertical rhythm:** `space-y-6` (24px) between PageHeader, KpiStrip, and primary content
- **Card content padding:** `p-6` (24px) — matches existing `<Card><CardContent>` pattern; do not reduce
- **Kanban card padding:** `p-3` (12px) — exception, kanban cards need to fit 4–6 per column at viewport widths ≥ 1024px. **Documented exception** to the 8-point scale; 12px is intentional for visual density.
- **Timeline row spacing:** `space-y-2` (8px) between entries within a day group; `space-y-6` (24px) between day groups
- **Heatmap cell size:** `h-3 w-3` (12px × 12px) — matches GitHub idiom; documented exception
- **Heatmap cell gap:** `gap-1` (4px)
- **Gantt bar height:** `h-6` (24px) per row; `gap-2` (8px) between rows
- **Donut chart container:** `h-40 w-40` (160px × 160px) — matches existing Recharts chart sizes in the codebase
- **Sparkline:** 64px × 16px (declared in research §"KpiStrip composition") — used inline inside SummaryCard accessory slot
- **Bulk-action toolbar height:** `h-12` (48px)
- **Touch target minimum:** 44px × 44px on mobile (iOS HIG). Kanban drag handle and gantt bar must meet this.

**Exceptions:** kanban card padding (12px), heatmap cell size (12px). Documented and intentional.

| Role | Size | Tailwind | Weight | Line height | Usage |
|------|------|----------|--------|-------------|-------|
| Display | 24px | `text-2xl` | 600 `font-semibold` | 1.2 (`leading-tight`) | KPI strip values, page H1 |

## Color

All colors are CSS variable references against the existing OKLCH theme in `src/app/globals.css`. **No new color tokens. No hex literals. Light + dark + high-contrast modes all share the same className contract.**

### 60 / 30 / 10 distribution

| Role | Variable | Tailwind class | Usage |
|------|----------|----------------|-------|
| Dominant (60%) | `--background` / `--card` | `bg-background`, `bg-card` | Page background, card surfaces |
| Secondary (30%) | `--muted` / `--secondary` / `--sidebar` | `bg-muted`, `bg-secondary`, `bg-sidebar` | Cards, sidebar, kanban column background, timeline day-group background |
| Accent (10%) | `--primary` | `bg-primary`, `text-primary`, `border-primary` | **Reserved for** (explicit list below) |

### Accent (`--primary`) is reserved for

- Primary CTAs (`Save`, `Submit`, `Approve`, `Apply Changes`)
- Active sidebar item
- Active tab indicator (kanban "Board" tab, timeline "Timeline" tab)
- KPI sparkline stroke
- Donut chart slice 1 (chart-1 = primary blue)
- Timeline UPDATE action dot
- Stepper active step indicator (`bg-primary` + `text-primary-foreground`)
- Gantt today-line vertical marker (`bg-primary`)
- Focus ring (`ring-ring`, which aliases `--primary`)
- Drag-hover indicator on kanban drop zones (`ring-2 ring-primary`)

**Accent is NOT used for:** secondary buttons, table headers, status badges (except those explicitly mapped to primary in STATUS_VARIANTS), card borders, breadcrumb separators, HEMS category labels, or general decoration.

### Status colors (do NOT override; reuse `STATUS_VARIANTS` from `src/lib/constants.ts`)

| Status enum value | Badge variant | Token rendered |
|-------------------|---------------|----------------|
| PENDING, ACTIVE, OPEN, SUCCESSOR, PARTIAL | `secondary` | `--secondary` background |
| STARTED, CLOSED, VACANT, RESIGNED, CLEAR, DISPUTED | `outline` | `--border` outline only |
| COMPLETE, SOLD, TRANSFERRED, RENTED, LISTED, CURRENT, PAID | `default` | `--primary` background |
| DISPOSED, FROZEN, LIEN, REMOVED, UNPAID | `destructive` | `--destructive` background |

**HEMS status badges** (declared locally in `HemsHistoryCard` per existing convention — STATUS_VARIANTS does not include HEMS statuses):

| HEMS status | Variant | Reason |
|-------------|---------|--------|
| PENDING | `secondary` | Awaiting review |
| APPROVED | `default` | Locked in, awaiting payout |
| DISTRIBUTED | `outline` | Terminal — paid out |
| DENIED | `destructive` | Terminal — denied |
| CANCELLED | `outline` | Terminal — withdrawn |

**HEMS categories are NOT badges.** The enum values HEALTH, EDUCATION, MAINTENANCE, SUPPORT are descriptive, not status. They render as plain `<span>` text (see §3 + Implementation Note 15) — using `Badge` would either fall through to the default variant (burning the reserved accent) or require polluting `STATUS_VARIANTS` with non-status keys.

### Semantic feedback colors

| Role | Variable | Usage |
|------|----------|-------|
| Success | `--success` | Positive KPI delta arrow + label, timeline INSERT dot, toast success bar |
| Destructive | `--destructive` | Negative KPI delta arrow + label, timeline DELETE dot, destructive button, error toast, validation error text |
| Warning | `--warning` | Upcoming-payoff bars in Gantt (within 30 days), heatmap legend "high activity" label |

**KPI delta color rule:**
- `delta.value >= 0` → `text-success` + `TrendingUp` icon
- `delta.value < 0` → `text-destructive` + `TrendingDown` icon
- For metrics where "down" is good (e.g. `currentBalance` shrinking on a paid-down loan, `pendingHemsCount` shrinking): pass `invertDelta: true` prop to KpiStrip item to flip the color mapping. Planner MUST add this prop to the `KpiStripItem` interface.

**This is a change to `SummaryCard`:** the current `trend.isPositive` flag is set by the caller and hardcoded to use `text-green-600` / `text-red-600` (lines 51–52). Patch `SummaryCard` to render `text-success` / `text-destructive` (no Tailwind colors) and the planner MUST include this patch as the first task of PR-1.

### 2. KpiStrip (Phase 1.3 — `src/components/kpi-strip.tsx`)

**Purpose:** Compose existing `SummaryCard` into a horizontal strip with optional sparklines. Used on 10+ pages.

**Props:**
```ts
interface KpiStripItem {
  label: string
  value: string | number                // already formatted by caller via formatMoney/formatPercent
  delta?: { value: number; label: string }   // % delta, e.g. { value: 12, label: "vs last 30d" }
  invertDelta?: boolean                 // flip color (e.g. liability balance going down is good)
  sparklineSeries?: number[]            // 7–30 datapoints
  icon?: LucideIcon                     // optional, passed to SummaryCard
}

interface KpiStripProps {
  data: KpiStripItem[]
  isLoading?: boolean
}
```

**Layout grid:**
- `< md` (768px): `grid grid-cols-1 gap-4` (stacked)
- `md` to `lg`: `grid grid-cols-2 gap-4`
- `≥ lg` (1024px): `grid grid-cols-4 gap-4`

**Card composition (each item):**
- Wraps existing `<SummaryCard>` — extend with `accessory?: ReactNode` prop in PR-1 (research §"KpiStrip composition" notes this gap)
- Title: `item.label` (`text-sm text-muted-foreground` — 14px / 400)
- Value: `item.value` (`text-2xl font-semibold tabular-nums` — 24px / 600)
- Delta row (if `delta` present): `TrendingUp` / `TrendingDown` icon + `Math.abs(item.delta.value)%` + `delta.label` in `text-xs`
  - Color via the invertible rule (see Color section)
- Sparkline (if `sparklineSeries` present): 64px × 16px Recharts `<LineChart>` in the accessory slot, top-right corner of card

**Loading state:** Render 4 `<SummaryCard isLoading />` skeletons (existing behavior).

**Empty state:** Render `<p className="text-sm text-muted-foreground">No data yet.</p>` — only happens if all items have null/zero values, which is acceptable for new entities.

**Per-page KPI columns (planner reference):**

| Page | KPI 1 | KPI 2 | KPI 3 | KPI 4 |
|------|-------|-------|-------|-------|
| `/dashboard` | Total assets | Total liabilities | Net worth | Cash on hand |
| `/accounts` | Account count | Total balance | Bank vs Investment ratio | 30d activity (sparkline) |
| `/assets` | Asset count | DOD total | Estimated current | Transfer-status progress |
| `/properties` | Property count | Total DOD value | Total current value | Total mortgage balance |
| `/vehicles` | Vehicle count | Total DOD value | Transfer % complete | Active count |
| `/insurance` | Policy count | Total coverage | Active count | Annual premium |
| `/trustees` | Trustee count | Current count | Successor count | (no 4th — 3-column variant) |
| `/bequests` | Bequest count | Total value | Distributed % | Pending count |
| `/personal-property` | Item count | DOD total | Estimated current | Categories tracked |
| `/contacts` | Contact count | Attorneys | CPAs | Other professionals |
| `/artwork` | Item count | DOD total | Estimated current | Insured count |
| `/liabilities` | Active count | Original principal sum | Current balance sum | Weighted avg APR |
| `/hems-queue` | Pending count | Approved count | Distributed total (30d) | Avg approval time (sparkline) |

### 3. Kanban — HEMS Queue Board (Phase 2.1)

**Purpose:** Drag-to-transition HEMS workflow. 3 columns. Read-only DISTRIBUTED column.

**Component:** Kibo UI `@kibo-ui/kanban` installed at `src/components/kibo-ui/kanban/index.tsx`.
**Consumer:** `src/app/(admin)/hems-queue/_components/HemsQueueBoard.tsx`.

**Columns:**
| ID | Label | Background | Description |
|----|-------|------------|-------------|
| PENDING | Pending | `bg-secondary` | Awaiting admin review |
| APPROVED | Approved | `bg-secondary` | Approved, awaiting payout |
| DISTRIBUTED | Distributed | `bg-muted` (more faded, terminal) | Read-only, no drop accepted |

**Column header style:**
- Layout: `flex items-center justify-between p-3 border-b border-border`
- Title: `text-sm font-semibold uppercase tracking-wide`
- Count badge: `<Badge variant="secondary" className="ml-2">{count}</Badge>`

**Card payload (per HEMS request):**

The HEMS category (HEALTH / EDUCATION / MAINTENANCE / SUPPORT) is **descriptive metadata, not status** — render as plain `<span>`, NOT a `<Badge>`. Using `Badge variant={STATUS_VARIANTS[category]}` would resolve to `undefined` and fall through to the `default` variant, burning the reserved `--primary` accent on every kanban card. See Implementation Note 15 for the rationale and the §Color section's "Accent is NOT used for" list which excludes HEMS categories.

```tsx
<div className="bg-card border border-border rounded-md p-3 shadow-sm space-y-2 cursor-grab">

    <span className="text-sm font-semibold">{beneficiaryName}</span>
    <span className="text-xs font-semibold uppercase tracking-wide text-muted-foreground">
      {category}
    </span>
  </div>
  <div className="font-mono tabular-nums text-sm font-semibold">
    {formatMoney(amountRequested)}
  </div>
  <div className="text-xs text-muted-foreground">
    Requested {formatDate(createdAt)} · {daysSince(createdAt)}d ago
  </div>
</div>
```

> Note: the money line uses `text-sm font-semibold` (14px / 600) — the prior `text-base` (16px) tier was dropped in revision 1.

**Card padding exception:** `p-3` (12px) — exception from 8-point scale to fit 4–6 cards per column at typical viewport widths.

**Drag affordances:** See "Drag affordances" in Color section.

**Drop transitions allowed:**
- PENDING → APPROVED: fires `trpc.hemsRequest.approve({ id, entityId, approvedAmount: req.amountRequested })`. Show `<ConfirmDialog>` first: "Approve {beneficiary}'s ${amount} request? This will create a distribution record."
- APPROVED → DISTRIBUTED: fires `trpc.hemsRequest.markDistributed({ id, entityId })` (new mutation per research A6). No confirm dialog (already approved).
- DISTRIBUTED → anything: blocked, `cursor-not-allowed`.
- Reverse drags (APPROVED → PENDING, DISTRIBUTED → APPROVED): blocked.
- Same-column reorder: no-op (kanban doesn't track within-column order for HEMS).

**Empty column copy:**
- PENDING empty: heading "No pending requests" / body "Beneficiaries will submit requests from the portal."
- APPROVED empty: heading "Nothing approved yet" / body "Approved requests appear here until distribution is paid."
- DISTRIBUTED empty: heading "No distributions yet" / body "Mark approved requests as distributed to record payouts."

Empty-state visual:
- Centered `<Icon>` (`Inbox` from lucide for PENDING, `CheckCircle2` for APPROVED, `Banknote` for DISTRIBUTED) at `h-8 w-8 text-muted-foreground`
- Heading: `text-sm font-semibold text-muted-foreground mt-2`
- Body: `text-xs text-muted-foreground mt-1 max-w-[160px] text-center`
- Padding: `py-8 px-4`

**Toast feedback:**
- Approve success: "Approved {beneficiary}'s ${amount} HEMS request."
- Approve error: "Couldn't approve this request — try again or refresh."
- markDistributed success: "Marked as distributed."
- markDistributed error: "Couldn't mark as distributed — verify the distribution record exists."

**Tabs above board:** `<Tabs>` from shadcn — "Board" (default) | "Table" (existing DataTable view, unchanged). Tab list uses `text-sm font-semibold`; active tab indicator uses `border-primary border-b-2`.

**Loading skeleton:** 3 columns each with 3 `<Skeleton className="h-24 rounded-md" />` cards.

**React Compiler safety:** Add `'use no memo'` at the top of `HemsQueueBoard.tsx` if `bun run build` log shows `[Compiler bailout]` for kibo kanban (per RESEARCH.md Pitfall 2 + PR #87 precedent).

## Accessibility Floor

- **Contrast:** All token combinations in light + dark + high-contrast meet WCAG AA (4.5:1 for body text, 3:1 for large text + UI components). Verified by existing high-contrast media query in globals.css.
- **Focus rings:** Use `outline-ring/50` from globals.css base layer. Every new interactive element must be keyboard focusable.
- **Touch targets:** 44px × 44px minimum on mobile for drag handles, chevrons, action buttons.
- **Screen reader:** All icon-only buttons require `aria-label`. Empty states should NOT be `aria-hidden`.
- **Drag-and-drop:** `@dnd-kit` (used by kanban, sortable, gantt) ships keyboard support + screen-reader announcements out of the box. Do not override.
- **`prefers-reduced-motion`:** Already respected in globals.css. New CSS transitions must wrap in `@media (prefers-reduced-motion: no-preference)`.
