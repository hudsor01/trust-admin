  <name>Task 1: Enable cacheComponents and define custom profiles</name>
  <files>next.config.ts</files>
  <action>
Add `cacheComponents: true` to the nextConfig object to enable Next.js 16's stable `"use cache"` directive support. Define three custom cacheLife profiles appropriate for trust administration:

```typescript
cacheComponents: true,
cacheLife: {
  // Tier 1: Financial data - fresh is critical
  financial: {
    stale: 30,        // 30 seconds
    revalidate: 60,   // 1 minute
    expire: 300,      // 5 minutes
  },
  // Tier 3: Reference data - changes infrequently
  reference: {
    stale: 300,       // 5 minutes
    revalidate: 600,  // 10 minutes
    expire: 3600,     // 1 hour
  },
  // Tier 4: Configuration - essentially static
  config: {
    stale: 600,       // 10 minutes
    revalidate: 3600, // 1 hour
    expire: 86400,    // 1 day
  },
},
```

Add after `reactStrictMode: false,` line in the nextConfig object. This enables Phase 39 to add server-side caching with these profiles while providing immediate TanStack Query benefits.

Avoid: Don't add any actual `"use cache"` directives to code yet — that's Phase 39's scope with cacheTag invalidation.

  <files>src/lib/trpc-provider.tsx</files>
  <action>
Update the QueryClient configuration to use sensible caching defaults for a financial application:

```typescript
new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 30,        // 30 seconds (was 5 seconds - too aggressive)
      gcTime: 1000 * 60 * 10,      // 10 minutes garbage collection
      refetchOnWindowFocus: false, // Already disabled, keep it
      refetchOnReconnect: true,    // Keep for reliability
    },
  },
}),
```

The key change is `staleTime` from 5 seconds to 30 seconds. This reduces unnecessary refetches while keeping financial data reasonably fresh. Add `gcTime` to keep cached data in memory longer for navigation performance.

Avoid: Don't set staleTime too high (e.g., 5 minutes) — financial data needs to stay reasonably fresh. Don't disable refetchOnReconnect — users returning from offline should get fresh data.
