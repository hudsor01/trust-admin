# Phase 10 Plan 04: Table Migration Batch 2 - Complex

**Migrate Dashboard, Bequests, Settings, and HemsQueue from manual Table to DataTable**

## Context

From Plan 10-02, the DataTable component now uses TanStack Table internally while maintaining backward compatibility with our custom ColumnDef interface. Pages currently using DataTable (4 pages) already benefit from TanStack Table features (sorting, type-aware columns, etc.) without any changes needed.

This plan targets the next batch of pages that use manual `<Table>` markup from shadcn/ui and converts them to use DataTable. These pages are considered "complex" because they have:
- Multiple tables per page
- Complex conditional rendering
- Inline actions
- Custom styling requirements

## Target Pages Analysis

### 1. Dashboard.tsx (688 lines)
**Tables:**
- Tasks table (incomplete tasks)
- Recent accounting entries table

**Complexity:**
- Dashboard layout with summary cards
- Task creation/editing dialog
- Checkbox for task completion
- Recent accounting preview (5 items)

**Migration approach:**
- Create TasksTable with DataTable
- Create RecentAccountingTable with DataTable
- Preserve all inline editing capabilities
- Keep summary cards unchanged

### 2. Bequests.tsx (476 lines)
**Tables:**
- Single bequests table

**Complexity:**
- Dialog form for create/edit
- Entity filtering
- Delete confirmation

**Migration approach:**
- Convert to DataTable with column configuration
- Use meta for onEdit/onDelete handlers
- Preserve dialog pattern

### 3. Settings.tsx (507 lines)
**Tables:**
- Configuration settings table

**Complexity:**
- Settings management (key-value pairs)
- Inline editing for values
- Add/remove settings

**Migration approach:**
- Convert to DataTable
- Preserve inline editing with EditableTextCell
- Keep add settings dialog

### 4. HemsQueue.tsx (460 lines)
**Tables:**
- HEMS requests table

**Complexity:**
- Approval/denial workflow
- Status badges
- Entity filtering
- Multiple actions per row (view, approve, deny)

**Migration approach:**
- Convert to DataTable with complex actions column
- Use meta for approve/deny handlers
- Preserve status badge rendering
- Keep entity filter
