## Context

**Current state**: `getAll()` returns full result sets without pagination
- Works fine for small datasets (hundreds of records)
- Will degrade with >1000 records per resource
- No way to request specific page of results

**Phase 9 goal**: Add optional pagination while maintaining backward compatibility
- Default behavior: Return all results (no breaking changes)
- Optional pagination: Specify limit, offset, return total count
- Type-safe: Leverage Phase 8 type improvements

### Task 1: Add pagination types to CrudOptions

Update the CRUD factory interface to support pagination:

```typescript
// db/crud-factory.ts

interface PaginationOptions {
  limit?: number      // Max records to return
  offset?: number     // Number of records to skip
  includeTotalCount?: boolean  // Whether to query total count
}

interface PaginatedResult<T> {
  data: T[]
  totalCount?: number  // Only present if includeTotalCount=true
  limit?: number
  offset?: number
  hasMore?: boolean    // Calculated: offset + data.length < totalCount
}
```

### Task 2: Update getAll() signature and implementation

Modify `getAll()` to accept optional pagination:

```typescript
async getAll(
  filterValue?: string,
  pagination?: PaginationOptions
): Promise<Select[] | PaginatedResult<Select>> {
  // Build base query
  let query = db.select().from(table as any)

  if (filterValue && filterColumn) {
    query = query.where(eq((table as any)[filterColumn], filterValue))
  }

  // If no pagination, return simple array (backward compatible)
  if (!pagination || (!pagination.limit && !pagination.includeTotalCount)) {
    const results = await query
    return results
  }

  // Paginated query
  const { limit, offset = 0, includeTotalCount } = pagination

  // Get total count if requested (separate query)
  let totalCount: number | undefined
  if (includeTotalCount) {
    const countQuery = db.select({ count: sql<number>`count(*)` })
      .from(table as any)

    if (filterValue && filterColumn) {
      countQuery.where(eq((table as any)[filterColumn], filterValue))
    }

    const [{ count }] = await countQuery
    totalCount = count
  }

  // Get paginated data
  if (limit) {
    query = query.limit(limit).offset(offset)
  }

  const data = await query

  return {
    data,
    totalCount,
    limit,
    offset,
    hasMore: totalCount !== undefined ? offset + data.length < totalCount : undefined
  }
}
```

**Important**:
- Use `sql<number>\`count(*)\`` for count query (Drizzle pattern)
- Maintain backward compatibility: No pagination options = return array
- Return type is union: `Select[] | PaginatedResult<Select>`

```typescript
// tests/crud-pagination.test.ts
import { describe, expect, test } from "bun:test"
import { entityCrud } from "../db/queries"

describe("CRUD Pagination", () => {
  test("getAll without pagination returns array", async () => {
    const result = await entityCrud.getAll()
    expect(Array.isArray(result)).toBe(true)
  })

  test("getAll with limit returns paginated result", async () => {
    const result = await entityCrud.getAll(undefined, { limit: 1 })
    expect(result).toHaveProperty("data")
    expect(result).toHaveProperty("limit", 1)
    expect(result).toHaveProperty("offset", 0)
    expect(Array.isArray(result.data)).toBe(true)
  })

  test("getAll with total count includes count", async () => {
    const result = await entityCrud.getAll(undefined, {
      limit: 1,
      includeTotalCount: true
    })
    expect(result).toHaveProperty("totalCount")
    expect(typeof result.totalCount).toBe("number")
    expect(result).toHaveProperty("hasMore")
  })

  test("getAll with filter and pagination works", async () => {
    // Assuming entities exist with entityId
    const result = await entityCrud.getAll(undefined, {
      limit: 10,
      offset: 0,
      includeTotalCount: true
    })
    expect(result.data).toBeDefined()
    expect(result.totalCount).toBeGreaterThanOrEqual(0)
  })
})
```

## Notes

**Cursor vs Offset Pagination**:
- Using offset pagination for simplicity
- Sufficient for trust admin use case (modest data volumes)
- Cursor pagination would be better for >10k records (Phase 10+ if needed)

**Performance**:
- Total count is separate query (can be slow on large tables)
- Make `includeTotalCount` optional so clients can skip if not needed
- Consider adding index on filterColumn if slow

**API Integration**:
- Plan 09-02 will update API routes to accept query params
- Plan 09-03 will add UI pagination controls
