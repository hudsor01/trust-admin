<objective>
Harden auth environment validation, centralize ADMIN_EMAIL access, add input validation to the reset-password API route, and ensure all password-change flows revoke existing sessions.

Purpose: Close four security gaps (SEC-01, SEC-02, SEC-03, SEC-05) identified in the v4.0 critical review. These are the highest-priority fixes -- a missing cookie secret breaks auth silently, an empty ADMIN_EMAIL could bypass owner checks, password resets leave old sessions alive, and the reset-password route accepts unbounded input.

Output: Hardened env validation, centralized env imports, Zod-validated reset-password route with session revocation, and corresponding tests.
</objective>

    1. In `src/app/api/auth/custom/reset-password/route.ts`, add Zod schema at top of file:
       ```typescript
       import { z } from 'zod'

       const ResetPasswordSchema = z.object({
           token: z.string().regex(/^[0-9a-f]{64}$/, 'Invalid token format'),
           newPassword: z.string().min(8, 'Password too short').max(128, 'Password too long'),
       })
       ```

    2. Replace the current input parsing (lines 11-17) with Zod validation:
       ```typescript
       const body = await request.json()
       const parsed = ResetPasswordSchema.safeParse(body)
       if (!parsed.success) {
           return NextResponse.json(
               { error: 'Invalid input' },
               { status: 400 },
           )
       }
       const { token, newPassword } = parsed.data
       ```
       IMPORTANT: Return generic "Invalid input" -- do NOT leak schema details (token format, length limits) in the error response.

               { tags: { subsystem: 'session-revocation' } },
