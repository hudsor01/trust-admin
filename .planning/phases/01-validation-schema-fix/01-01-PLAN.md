# Plan 01-01: Create Schema Wrapper Utility

**Phase:** 1 - Validation Schema Fix
**Created:** 2026-01-09
**Status:** Ready to execute

---

## Objective

Create a reusable wrapper utility around `createInsertSchema()` that automatically makes auto-generated fields (`id`, `createdAt`, `updatedAt`) optional, eliminating the need to manually specify `.optional()` for these fields in every schema.

**Success Criteria:**
- Wrapper function created and tested
- One schema successfully migrated as proof of concept
- API POST endpoint for test schema works (no 400 errors)

---

## Context

**Problem:** drizzle-zod v0.8.3's `createInsertSchema()` requires ALL fields to be explicitly marked `.optional()` if they shouldn't be required in insert operations. Currently, auto-generated fields (`id`, `createdAt`, `updatedAt`) are NOT marked optional, causing ALL POST endpoints to return 400 validation errors.

**Current Pattern (broken):**
```typescript
export const insertLiabilitySchema = createInsertSchema(liability, {
  creditor: (schema) => schema.min(1, "Creditor is required"),
  // Missing: id, createdAt, updatedAt should be .optional()
});
```

**Architecture Context:**
- CRUD factory (`db/crud-factory.ts`) auto-generates these fields if not provided
- Route factory (`index.ts:156-250`) validates with Zod before calling CRUD operations
- All 31 tables affected

**From CONCERNS.md:**
- Line 21-27: Manual enum type casting issue (will address in Phase 8)
- This plan focuses ONLY on fixing auto-generated field validation

## Tasks

### Task 1: Create schema wrapper utility

**File:** `db/validation.ts` (add at top after imports, before existing schemas)

**Implementation:**
```typescript
/**
 * Wrapper around createInsertSchema that automatically makes auto-generated
 * fields optional (id, createdAt, updatedAt).
 *
 * This fixes drizzle-zod v0.8.3 behavior where ALL fields are required by default.
 *
 * @param table - Drizzle table definition
 * @param customizations - Custom Zod refinements for specific fields
 * @returns Zod schema with auto-generated fields marked optional
 */
export function createInsertSchemaWithDefaults<T extends PgTable>(
  table: T,
  customizations: Record<string, (schema: any) => any> = {}
) {
  return createInsertSchema(table, {
    // Auto-generated fields should always be optional
    id: (schema) => schema.optional(),
    createdAt: (schema) => schema.optional(),
    updatedAt: (schema) => schema.optional(),
    // Apply custom validations for other fields
    ...customizations,
  });
}
```

**Acceptance:**
- Function compiles without TypeScript errors
- Generic type `T extends PgTable` allows any Drizzle table
- Customizations spread after defaults (allows overriding if needed)

### Task 2: Test wrapper with one schema

**File:** `db/validation.ts` - Replace `insertLiabilitySchema` definition

**Before:**
```typescript
export const insertLiabilitySchema = createInsertSchema(liability, {
  creditor: (schema) => schema.min(1, "Creditor is required"),
  originalAmount: (schema) => schema.refine(
    (val) => parseFloat(val) > 0,
    "Original amount must be greater than 0"
  ),
  // ... other validations
});
```

**After:**
```typescript
export const insertLiabilitySchema = createInsertSchemaWithDefaults(liability, {
  creditor: (schema) => schema.min(1, "Creditor is required"),
  originalAmount: (schema) => schema.refine(
    (val) => parseFloat(val) > 0,
    "Original amount must be greater than 0"
  ),
  // ... other validations (keep all existing)
});
```

**Acceptance:**
- No TypeScript compilation errors
- Existing liability validation rules preserved
- `id`, `createdAt`, `updatedAt` now optional in schema

### Task 3: Verify API endpoint works

**Test:** Manual API call to verify fix

**Steps:**
1. Start PostgreSQL: `docker start trust-admin-postgres` (if not running)
2. Start API server: `bun run dev:api`
3. Make POST request:
```bash
curl -X POST http://localhost:5050/api/liabilities \
  -H "Content-Type: application/json" \
  -d '{
    "entityId": "entity-hudson-trust",
    "creditor": "Test Creditor",
    "liabilityType": "LOAN",
    "originalAmount": "10000.00",
    "currentBalance": "10000.00"
  }'
```

**Expected Result:**
- Status: 201 Created
- Response body contains created liability with auto-generated `id`, `createdAt`, `updatedAt`
- NO validation errors about missing `id` or `updatedAt`

**Actual Result Before Fix:**
```json
{
  "error": {
    "message": "Validation failed: 2 field(s) have errors",
    "details": {
      "fields": {
        "id": "Invalid input: expected string, received undefined",
        "updatedAt": "Invalid input: expected string, received undefined"
      }
    }
  }
}
```

**Acceptance:**
- POST succeeds with 201 status
- Created liability has valid `id` (nanoid format)
- `createdAt` and `updatedAt` are ISO timestamp strings
- Can verify in database or via GET `/api/liabilities/{id}`
