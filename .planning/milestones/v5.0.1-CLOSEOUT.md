## Overview

After v5.0 was formally archived at PR #126 on 2026-05-22, a comprehensive sweep ran to audit the milestone's actual delivery, close out deferred test-backfill items, fix UI patterns that turned out wrong in production, and prune accumulated dead code. The total scope grew beyond a "polish pass" — 9 PRs, 5 components removed from the app, 1 runtime bug fixed, 39 orphan files deleted, 8 unused npm dependencies dropped, ~50 new tests written, and a retroactive Nyquist validation backfill for 4 phases.

The work didn't expand v5.0's requirement scope — every change either documented what shipped, fixed something that turned out worse-than-acceptable in production, or removed code/deps that weren't earning their keep. Formalizing this as v5.0.1 captures the audit trail so future maintainers can find the "what happened between v5.0 ship and v6.0 start" answer in one place.

## Changes by area

### Bug fixes
- **`createContext` RSC cookie-write** — surfaced by battle test, fixed in PR #135. Affects every authenticated SSR request to admin pages using `createTRPCHelpers`. Was logging `⨯ Cookies can only be modified in a Server Action or Route Handler` on every `/dashboard` render. Now silenced; layout-guard redirect handles the cookie-refresh round-trip via Route Handler context.

### UI cleanup (post-deploy user feedback)
- Removed `BeneficiaryShareDonuts` row from `/beneficiaries` — rendered 3 empty placeholder donuts ("share not set") when sharePercent wasn't populated. Same redundant-when-empty pattern as the avatar stack deleted in Phase 33.
- Removed "Order of Service" drag-reorder card from `/trustees` — analogous to the deleted Beneficiaries "Display Order" section. `trustee.order` column + `idx_trustee_entity_order` index + `orderBy(asc(trustee.order))` preserved (display order across the app remains identical).

### Dead-code cleanup
- 36 orphan files deleted: 4 db utilities, 7 one-off migration scripts, 5 public-inventory-form scaffolding, 2 unused charts, 2 orphan kibo-ui, 11 orphan shadcn primitives, 4 utility components/hooks, 1 upload helper.
- 8 dependencies removed: `@diceui/combobox`, `@diceui/tags-input`, `@radix-ui/react-avatar`, `@uploadthing/react`, `react-day-picker`, `react-dropzone`, `bcryptjs`, `@types/bcryptjs`. Net ~50MB dev `node_modules` shrink.
- 165 unused exports + 43 unused types pruned across `src/lib/`, `db/`, `src/server/trpc/`. Includes 35+ `select*Schema` auto-generated exports from `db/validation.ts`, the unused `publicProcedure` from `src/server/trpc/init.ts`, the `personalPropertyCrud` hand-written CRUD from `db/queries.ts`, and 14 scaffolding helpers across `src/lib/*` (`sentry.ts` trace helpers, `auth-events.ts` whole file, `form-factory.ts` factories, `money.ts` arithmetic, etc.).

## Outstanding (acceptable, can't fix without upstream)

- **Sentry DEP0205 suppression** — `@sentry/node-core@10.53.1` still calls `module.register()` instead of `module.registerHooks()`. Suppressed via `NODE_OPTIONS='--disable-warning=DEP0205'` on `dev`/`build`/`build:analyze`/`start` scripts in `package.json`. Removable once upstream Sentry releases the migration. Tracked in `STATE.md` "Key Decisions" (`[Phase 32]` entry) and the v5.0 audit's tech-debt section.
- **Phase 28/29 Nyquist `wave_0_complete: false`** — documented in their `VALIDATION.md` files as deferred during the milestone audit (carry-over from v4.0 advisory). Not a v5.0 acceptance criterion. Backfill with `/gsd:validate-phase <N>` when prioritized.
- **`trustee.order` schema tightening (D-14-equivalent for trustees)** — unlike `beneficiary.sortIndex` (which has `default(0)`), `trustee.order` is `notNull` with no DB default. `.omit({ order: true })` from `insertTrusteeSchema` would break `trustee.create`. Schema-level omission requires migration 0015 adding the default. Deferred. Tracked in `db/validation.ts` inline comment + PR #132 commit body.
- **`KpiStripItem` interface drift docs** — minor; PR #128 corrected the snippet in PLAN docs but the runtime contract was always correct.
