## Overview

Two thematically independent threads shipped in one milestone:

1. **Firearms as a first-class trust asset class** — new `firearm` table with full regulatory fields (serial #, NFA classification, FFL/ATF Form 5 transfer status, condition grade, acquisition cost), dedicated `firearmRouter` tRPC, `/firearms` admin page with 3-step wizard + DataTable, dashboard + `/assets` aggregator integration, and sidebar navigation alphabetization with the new entry.

## Milestone Summary

**Key Decisions (extracted from STATE.md and per-phase CONTEXT files):**

- `firearm` is the 8th asset class — follows the `vehicle.ts` pattern exactly (same shared columns: `entityId`, `dodValue`, `dodValueDate`, `status`, `transferStatus`; same RLS policies; same router shape). Carries 5 firearm-specific enums in addition.
- `nfaTransferStatus` is a 3-value enum (`NOT_FILED | FILED | APPROVED`) separate from the generic `transferStatus` enum — different lifecycles, different progress models.
- `valuation.firearmId` + `document.firearmId` FKs ship in Phase 28 with updated single-owner CHECK constraints (one-asset-per-doc invariant preserved).
- `SURRENDERED` on the shared `transferStatus` enum is OUT OF SCOPE — `nfaRegistered` flag + notes cover unregistered NFA items without touching every asset table.
- Beneficiary cleanup (Phase 33) is fully independent of firearms phases — no shared files, no schema changes.
- `BeneficiarySortableList.tsx`, `WithdrawalMilestoneGantt.tsx`, `BeneficiaryAvatarStack.tsx`, `tests/trpc/beneficiary-reorder.test.ts` deleted in Phase 33; the `beneficiary.reorder` adminProcedure deleted too.
- `beneficiary.sortIndex` column + `idx_beneficiary_entity_sort` composite index + `asc(beneficiary.sortIndex)` ORDER BY in `beneficiary.list` are PRESERVED (BENE-04 invariant) — drag-reorder UI is removed but persistent display order stays.
- `KpiStrip` skeleton + loaded branches share a single `cn(...)` conditional that derives both grid columns AND tile count from `data.length`. Reusable pattern eliminates first-render layout jump for any 5+ tile caller.

**Patterns Established:**

- **Asset admin page (8th iteration)** — copy-and-modify from `VehiclesClient.tsx` with NFA + CQS additions. Established for future asset-class additions.
- **CQS UI affordance** — dedicated `NfaStatusDialog` separated from generic `FirearmDialog`; the ONLY UI path to mutate `nfaTransferStatus`. Forces explicit intent for status transitions.
- **`formInstance.Subscribe<boolean>` conditional section** — first use in an asset dialog (precedent set by `ContactDialog`); now established for any conditionally-required form field.
- **DataTable `meta.excludeFromExport` + `initialColumnVisibility.location=false`** — defense-in-depth for sensitive CSV columns (location-of-firearm is high-PII).
- **TRPC CONFLICT client handling on duplicate serial** — `TRPCClientError` + `err.data?.code === 'CONFLICT'` + toast + keep-dialog-open pattern.
- **Sidebar prefetch handlers are cache-warming primitives** — React Query `staleTime: 1000 * 60 * 5` makes hover network calls fire only on cold cache. UAT methodology for hover-prefetch must hover on cold cache or verify via JSX inspection + dev log of first-hover fire.
- **tRPC v11 `httpBatchLink` uses GET for queries, POST for mutations** — sidebar prefetches are GETs (e.g. `/api/trpc/firearm.list?batch=1&input=...`). Plan/UAT specs should reflect this.
- **Sentry DEP0205 suppression** — `@sentry/node-core@10.53.1` still calls `module.register()` instead of `module.registerHooks()`. Suppressed via `NODE_OPTIONS='--disable-warning=DEP0205'` on `dev`/`build`/`build:analyze`/`start` scripts. Removable once upstream Sentry releases the migration.
- **`KpiStrip` derive-from-data** — both skeleton and loaded branches use `cn('grid grid-cols-1 md:grid-cols-2 gap-4', data.length === 5 ? 'lg:grid-cols-5' : 'lg:grid-cols-4')` with tile count from `data.length`. Reusable for any future 5+ tile strip.
- **Surgical-delete execution order** — edit consumer first (remove imports + JSX), then `git rm` the orphaned components, then prune downstream server-side surface. Avoids transient broken-import windows.
- **UI-SPEC FLAG → CONTEXT promotion** — UI-SPEC FLAGs are advisory by GSD convention; the planner may treat them as out-of-scope cosmetic. To make a FLAG mandatory, promote it to a CONTEXT.md `[MANDATORY TASK]` decision with verbatim diff shape BEFORE dispatching the planner. CONTEXT is the planner's source of truth.

**Issues Resolved:**

- Phase 32 SC-3 false-alarm — browser UAT initially reported SC-3 as DEVIATION because hovering Firearms (and most other Assets sub-items) emitted zero tRPC requests. Investigation revealed the test ran on a warm React Query cache (`staleTime: 5min`). The dev log proved `firearm.list` DID fire on first cold-cache hover. SC-3 wiring confirmed correct via 3 independent evidence layers.
- Phase 31 SC-2 false-alarm — initial verification reported the "Firearms" allocation pie chart slice as absent. Database had zero firearm rows with non-zero `dodValue`; once test data was added, the slice appeared. Verification methodology updated to seed test data before checking allocation visualizations.
- Sentry DEP0205 noise on dev startup discovered during Phase 32 UAT — suppressed via `NODE_OPTIONS='--disable-warning=DEP0205'` on the 4 next.js scripts.
- ROADMAP Phase 31 progress table showed `0/1 plans complete` while the phase row was marked Complete — pre-existing inconsistency, fixed during Phase 32 closeout.
- `next-env.d.ts` showed as modified on every fresh checkout — Next.js 16 moved dev types from `.next/types/` to `.next/dev/types/`. Committed the regen during Phase 32 closeout.

**Issues Deferred (out of scope, tracked):**

- `beneficiary.sortIndex` auto-management (ROW_NUMBER backfill or insertion order) — if drag-reorder UI never returns, the column could become server-auto-managed. Out of scope for v5.0; logged in 33-CONTEXT.md Deferred Ideas.
- `beneficiary.create` / `beneficiary.update` sortIndex input handling — both writers currently accept `sortIndex` in their schemas. Not touched by Phase 33 (D-14). Separate future phase could tighten the schemas.
- ATF Form 5 / eForms e-filing integration — explicitly out of scope (no third-party API available).
- NICS / background-check / prohibited-person verification — explicitly out of scope (FFL-only system; unauthorized access is a federal offense).
- Ammo inventory, ballistic data, accessories tracking — explicitly out of scope (not estate administration concern).
- Gun-trust "responsible persons" schedule / ATF 5320.23 — explicitly out of scope (Hudson Trust is not a dedicated NFA gun trust).
