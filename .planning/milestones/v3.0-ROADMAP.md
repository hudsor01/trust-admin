# Milestone v3.0: Database Schema Improvements

**Status:** ✅ SHIPPED 2026-01-18
**Phases:** 18-24 (7 phases)
**Total Plans:** 8

## Overview

Apply PostgreSQL best practices to the database schema based on official Drizzle and PostgreSQL documentation. Address all identified schema issues systematically with proper research, migration strategies, and rollback plans.

**Why This Mattered:**
- Current schema used `timestamp` instead of `timestamptz` (timezone issues)
- TEXT primary keys instead of BIGINT IDENTITY (performance, storage)
- Polymorphic tables lacked constraints (data integrity)
- Missing composite indexes (query performance)
- Text fields used where enums should be (type safety)
- PascalCase table names against PostgreSQL conventions

## Milestone Summary

**Key Decisions:**
- Pattern: `bigint({ mode: 'number' }).primaryKey().generatedAlwaysAsIdentity()` for PKs
- Pattern: `z.coerce.number()` for ID validation in tRPC routers
- Decision: Better Auth tables keep TEXT IDs, application tables use BIGINT
- Decision: recordId stays text for polymorphic activity logging
- Decision: Table names use snake_case, TypeScript variables stay camelCase

**Issues Resolved:**
- Fixed timezone inconsistencies with TIMESTAMPTZ migration
- Added type safety with pgEnums
- Enforced data integrity with CHECK constraints
- Improved query performance with composite indexes
- Modernized PK strategy from TEXT to BIGINT IDENTITY
- Aligned with PostgreSQL naming conventions

**Issues Deferred:**
- FK constraint names in database still PascalCase (cosmetic, will be renamed on next drizzle-kit push)

**Technical Debt Incurred:**
- None significant
